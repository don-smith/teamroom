Team Room architecture

Team Room runs a team of AI agents in isolated containers. One daemon handles connections and model access for the machine, and each repository gets its own daemon for mail, storage and agent sessions.

How a message travels

  1. 1
    You send a message from the CLI or Telegram.
  2. 2
    The Team Room daemon finds the repository that should receive it.
  3. 3
    The message crosses the WebSocket link. The repo daemon is started first if it is not running.
  4. 4
    The mail dispatcher receives the message and saves it to SQLite.
  5. 5
    The dispatcher announces the delivery on the repo's event bus.
  6. 6
    Session management starts the agent's container or wakes the running one.
  7. 7
    The agent calls its model through the proxy. The container holds only a routing token, never the real key.
  8. 8
    The agent replies with its mail tools. The reply returns over the link to the CLI or Telegram.
