# Team Room M1 — As Built

*Date: 2026-04-18. Frozen at commit. Future changes happen in a new as-built, not here.*

## 1. What was delivered

Milestone 1 — *"One agent that works."* A single hand-configured agent (`assistant`) runs in a fresh Docker container per turn, invoked through a `teamroom` CLI (`serve`, `send`, `tail`, `status`). End-to-end smoke test passed against a local LM Studio instance running `qwen/qwen3.5-9b`. Full test suite: 68/68 across 21 files, completing in ~1.5 s.

Exit criteria from the spec were met:

- Message sent via `teamroom send` → processed by the hand-configured agent in a fresh Docker container → reply visible via `teamroom tail`.
- No agent onboarding tooling; the first agent is hand-crafted.
- Structured JSON logs with trace IDs flow CLI → daemon → container → reply.
- Daemon can be killed at any point; a reconcile pass on startup handles orphaned turns deterministically.
- Every effectful dependency sits behind an interface; no mocking libraries anywhere.

One adaptation landed during smoke-test prep: the original spec called for Anthropic's hosted API with `ANTHROPIC_API_KEY`; the shipped build uses an OpenAI-compatible local model endpoint (LM Studio) and renames the downstream-milestone "credential proxy" to **model proxy / model abstraction layer**. §4 below documents the pivot; M2 will generalise the abstraction.

## 2. Architecture as built

### Processes and boundaries

- **`teamroom` CLI (host, short-lived).** Four subcommands: `serve` (starts the daemon), `send` (queues an inbound message in SQLite), `tail` (subscribes to the bus and streams outbound replies), `status` (reports liveness + per-status turn counts). Entry at `src/cli/main.ts`.
- **Daemon (host, long-lived).** Owns the SQLite connection, polls for pending inbound messages, spawns one container per turn. Entry at `src/daemon/main.ts`. Single orchestrator loop; serialises per agent.
- **Agent container (Docker, per-turn, ephemeral).** Spawned by the daemon per inbound message. Reads one JSON envelope on stdin, loads `conversation.jsonl` from the mounted `/store`, calls an OpenAI-compatible LLM, writes `type: "reply"` events on stdout, appends to conversation, exits. Image: `teamroom-agent-assistant:latest` (~232 MB; `node:20-alpine` base).

The host/container split is the load-bearing architectural seam. Everything under `src/` except `src/agent-runtime/` runs on the host; `src/agent-runtime/` is baked into the agent image and never imported by host code.

### Module layout (`src/`)

```
src/
├── types.ts              # shared domain types (Agent, Message, Turn, BusEvent)
├── clock/                # Clock interface + SystemClock + ControllableClock
├── logger/               # Logger interface + JsonLinesLogger + CapturingLogger
├── env/                  # readEnvFile() — no process.env pollution
├── db/                   # SQLite + migrations + AgentRepo/MessageRepo/TurnRepo
├── bus/                  # NotifyBus seam (FileNotifyBus prod / InMemoryBus test)
├── container/            # ContainerRunner seam (DockerRunner prod / FakeRunner test)
├── agent-config/         # host-side loader for agents/<name>/ folders
├── daemon/               # composition root, orchestrator, turn-processor, reconcile, safety-nets
├── cli/                  # teamroom CLI (serve/send/tail/status)
└── agent-runtime/        # what runs INSIDE each container (openai SDK + session store)
```

Every multi-file module has a README with one-paragraph contract, one-paragraph boundary statement (where/when it runs), `## Files`, and a `## Related` link block (Parent / Uses / Used by / Spec / Memory). Follow `## Related` to navigate the repo as a knowledge graph.

### Data model

SQLite at `data/teamroom.db`, migrated via `src/db/migrator.ts` using a `_migrations` ledger for idempotency. Three tables:

- **`agents`** — `id`, `config_path`, `created_at`.
- **`messages`** — `id`, `agent_id`, `channel`, `direction ('in'|'out')`, `body`, `turn_id`, `trace_id`, `created_at`. Indexes on `(agent_id, created_at)` and `(direction, created_at)`.
- **`turns`** — `id`, `agent_id`, `inbound_message_id`, `status ('pending'|'running'|'done'|'error')`, `container_id`, `error`, `trace_id`, `started_at`, `finished_at`, `created_at`. Index on `status`.

### Event bus

`NotifyBus` is the pub/sub seam. `FileNotifyBus` (prod) writes to `data/bus/events.jsonl` and reads via chokidar polling with id deduplication. `InMemoryBus` (tests) is a real in-process pub/sub — not a mock. Event shapes:

- `message.outbound` — a reply is available for `turn_id`.
- `turn.started` / `turn.completed` / `turn.errored` — lifecycle.

### Container contract (host ↔ container)

On spawn the daemon provides:

- **Mounts:** `/AGENTS.md` (read-only, from `agents/<name>/AGENTS.md`), `/store` (writable, from `agents/<name>/store/`).
- **Env:** `TEAMROOM_MODEL_BASE_URL`, `TEAMROOM_MODEL_API_TOKEN`, `TEAMROOM_MODEL`, `TEAMROOM_TURN_ID`, `TEAMROOM_TRACE_ID`, `TEAMROOM_AGENT_ID`.
- **Stdin:** one JSON envelope `{ inbound: { body, traceId, channel }, turnId, agentId }`.
- **Stdout:** JSONL events, at least one `{ "type": "reply", "body": "..." }`. Terminal `{ "type": "done" }` optional.
- **Timeout:** daemon kills the container after the configured wall-clock window.
- **Exit codes:** 0 = clean; non-zero = runner surfaces stderr tail as `error` on the turn row.

### Agent folder shape (`agents/assistant/`)

- `agent.yaml` — `name`, `model`, `image_tag`.
- `AGENTS.md` — model-facing instructions (mounted into the container).
- `Dockerfile` — builds the per-agent image with `src/agent-runtime` baked in.
- `store/` — per-agent writable state. `conversation.jsonl` accumulates here; `.gitkeep` retains the folder in git.

### Turn lifecycle

1. `send` writes an inbound `messages` row (direction `in`, no `turn_id`).
2. Orchestrator polls for pending inbound messages.
3. `processTurn` creates a `turns` row (`status='pending'`), spawns the container, streams stdout events.
4. Each `type: "reply"` event becomes an outbound `messages` row (direction `out`) plus a `message.outbound` bus event.
5. Container exit transitions the turn to `done` or `error`; corresponding `turn.completed` / `turn.errored` bus event fires.
6. `tail` subscribes to `message.outbound` and fetches bodies from SQLite to print.

### Testability

Every effectful dependency (`Clock`, `Logger`, `NotifyBus`, `ContainerRunner`, `LlmClient`) sits behind an interface. Tests use in-memory **real** implementations (`SQLite :memory:`, `InMemoryBus`, `FakeRunner`) — never `vi.mock`. Unit tests are co-located (`src/<module>/<file>.test.ts`); integration lives at `tests/integration/end-to-end.test.ts`. `tsc` excludes `**/*.test.ts` from the build.

## 3. Key design decisions and their WHY

- **DI-first architecture with interface seams at every effectful boundary.**
  - **Why:** testability without mocking libraries; real implementations at small scale are cheaper than stubs and less likely to rot. The Anthropic→OpenAI pivot touched one seam (`LlmClient`) and was absorbed in minutes — the decision paid for itself inside M1.

- **No long-running dependencies beyond the daemon itself.** SQLite is embedded; the bus is a file; there is no broker.
  - **Why:** minimises process topology; every added long-running service is one more thing that can be partially running, partially configured, or partially alive during development.

- **Nothing silent, nothing inconsistent, nothing crashes.** Global `uncaughtException` / `unhandledRejection` handlers in `src/daemon/safety-nets.ts` log fatal and do **not** exit; reconcile on startup marks orphaned `running` turns as errored with `'daemon_restart'`.
  - **Why:** a daemon that silently drops turns is worse than one that errors loudly. The system must behave deterministically across crash boundaries.

- **Daemon is procedural; intelligence lives in agent containers.**
  - **Why:** separate concerns cleanly: the daemon is a conveyor belt; per-agent reasoning is a container's responsibility. Containers are easy to replace, freeze, or swap language.

- **Container contract is language-agnostic JSONL over stdio.**
  - **Why:** agents can be written in any language that can read stdin and write stdout. M1 ships TypeScript; M4+ `agent-runtime` could be LangGraph (Python) without touching the daemon — see `docs/memory/project_teamroom_langgraph_direction.md`.

- **`NotifyBus` seam separated from "did the reply get stored."**
  - **Why:** replies are durable in SQLite independent of bus delivery. Subscribers fetch bodies from the DB keyed by `turn_id`; the bus is only a notification channel. Prevents a flaky bus from corrupting delivery.

- **Per-agent folder layout with `agent.yaml` + `AGENTS.md` + `Dockerfile` + `store/`.**
  - **Why:** each agent is a self-contained unit. `agent.yaml` is the config surface; `AGENTS.md` is mounted into the container as its standing instructions; `store/` is the only writable mount. M2+ onboarding tooling will scaffold this shape.

- **Renamed `CLAUDE.md` → `AGENTS.md` inside the container mount.**
  - **Why:** model-agnostic. Claude, OpenAI-compatible models, and future agents all read the same file. The name is the contract.

- **Session file is `conversation.jsonl`, not an opaque `session-id`.**
  - **Why:** the container builds the LLM call from a readable append-only log. Debuggable, grep-able, and independent of any particular SDK's session format.

- **`readEnvFile()` reads `.env` into a plain object; it does not pollute `process.env`.**
  - **Why:** tests can run with different env sets without leaking across each other. Production code asks for what it needs explicitly.

- **Co-located unit tests (`src/<module>/<file>.test.ts`), `tests/integration/` only for cross-module.**
  - **Why:** refactors stay local; any file's source and tests are one directory read away. See retro §2 for the history — this was adopted late in M1, decisively.

- **`## Related` README convention at every multi-file module.**
  - **Why:** makes the repo a navigable graph: Parent → Uses → Used by → Spec → Memory. New agents orient by following links rather than grepping filenames.

- **Memories live in `docs/memory/`, not in a Claude-private directory.**
  - **Why:** in-repo memory is visible to git, to the user, and to any AI agent — not only the Claude Code session that wrote it. If the codebase is the knowledge graph, memories belong in the codebase. See closeout §D1.

## 4. Adaptations during execution

- **Anthropic hosted API → OpenAI-compatible local LLM (LM Studio).** The original spec used the Anthropic SDK with `ANTHROPIC_API_KEY`. During smoke-test prep we pivoted to an OpenAI-compatible endpoint (LM Studio running `qwen/qwen3.5-9b`) so the smoke test could run without external credentials. Changes: `src/agent-runtime/main.ts` uses the `openai` package; env vars became `TEAMROOM_MODEL_BASE_URL` + `TEAMROOM_MODEL_API_TOKEN` + `TEAMROOM_MODEL`; spec §9 container contract updated accordingly.

- **"Credential proxy" renamed to "model proxy / model abstraction layer."** The M2+ abstraction was always about providing the model endpoint to containers; the new name reflects that the proxy abstracts model backends rather than just credentials.

- **`agents/<name>/CLAUDE.md` → `AGENTS.md`** inside the container mount. Model-agnostic naming.

- **`agents/<name>/store/session-id` → `agents/<name>/store/conversation.jsonl`.** Readable append-only log instead of an opaque id.

- **`tests/unit/...` pattern → co-located `src/<module>/<file>.test.ts`.** Refactor landed in commit `44d9d8e` after the unit/integration split proved noisy during module moves.

- **Seven plan drifts caught and fixed in-flight**, all now also documented here so the closeout can purge `docs/tabled.md`:
  1. **FileNotifyBus chokidar readiness race.** Plan published events before `ready` — fixed with `await watcher.on("ready", ...)` before initial drain.
  2. **FileNotifyBus `close()` didn't wake sleeping iterators.** Fixed with a bus-level `sleepingResolvers: Set<() => void>`.
  3. **FileNotifyBus named-type import** — `chokidar.FSWatcher` after default-only import failed strict TS; fixed with `import chokidar, { type FSWatcher } from "chokidar"`.
  4. **`buildDockerRunArgs` env order** — plan test 1 was inconsistent with plan test 2 and the implementation (alphabetical sort). Test 1's expected argv corrected.
  5. **`parseEvent` spread ordering in `docker-runner.ts`** — malformed JSON could overwrite the typed `type` field. Not blocking at M1 (warn-logged and dropped) but flagged for pre-M2 touch of `parseEvent`.
  6. **Anthropic SDK `TextBlock` type narrowing** — predicate `b is { type: "text"; text: string }` is incompatible with the `@anthropic-ai/sdk@0.65` `ContentBlock` union (requires `citations`). Replaced with filter + cast. *Superseded by the LM Studio pivot; no longer load-bearing.*
  7. **`.gitignore` exception for `.gitkeep` inside an excluded directory.** `agents/*/store/` + `!agents/*/store/.gitkeep` does not work — git can't re-include files inside an excluded parent. Fixed by switching to `agents/*/store/*` + `!agents/*/store/.gitkeep`. Workaround `git add -f` retired.

- **Added spec sections that were missing from the original.** Configuration and secrets (dotenv pattern, `.env` gitignored, single-key-per-line), and test layout (co-located unit, `tests/integration/` for cross-module, `**/*.test.ts` excluded from `tsc`).

- **Subagent protocol pivot mid-milestone.** Started with strict per-task implementer-plus-reviewer dispatches; pivoted to batched implementer + single review pass per batch. Reduced subagent count by ~2/3 without degrading quality (real defects still caught — `@types/node` drift, FileNotifyBus bugs, `buildDockerRunArgs` inconsistency). Review cadence should follow task complexity, not position in a sequence.

## 5. Known limitations and debts for future work

- **Reconciler blind spot: `pending` turns with running containers.** `processTurn` calls `turnRepo.markRunning` *after* `runner.run()` returns, so during the actual container run the turn row is `status='pending'` with `container_id=NULL`. Task 16's reconciler only reclaims `status='running'` turns — it will miss a turn whose daemon crashed mid-container. M2 options: (a) `markRunning` before `runner.run()` (runner surfaces a placeholder id up-front), or (b) reconciler reclaims aged `pending` turns too. Retro §3 flags this for the spec; tracked here.

- **Daemon shutdown polish.** Three items from Task 16–18 review:
  - `src/daemon/daemon.ts:61–62` uses a dynamic `import("node:fs")` without justification — consolidate to top-level static import.
  - `stop()` does not unlink the PID file — stale PID after clean shutdown.
  - `shutdown` in `src/daemon/main.ts` is not idempotent under rapid SIGINT+SIGTERM; `db.close()` on an already-closed better-sqlite3 DB throws. Add a `let stopped = false` guard.

- **`parseEvent` spread-ordering drift** (see §4). Malformed JSON path is warn-logged and dropped; fix before anything else touches `parseEvent`.

- **`@types/node` version vs. runtime target.** `package.json` pins `@types/node@^22.8.0` but `engines.node` is `>=20`. Node-22-only APIs won't be caught by TS against a Node-20 target. Closeout §Task H re-evaluates — may be resolved by switching to `^20`.

- **Runbook template for agent onboarding.** Deferred per "see only as far as needed" — the first onboarding runbook will be written when M2 hires the second agent. Skill/runbook boundary partially resolved in closeout §D4.

- **Configuration knobs are minimal.** Only `LM_STUDIO_API_TOKEN` is required in `.env` for M1. `.env.example` is created in closeout §Task F.

- **No CI.** The full suite runs locally in ~1.5 s; CI is a post-M1 adjunct when the build touches more than one developer.

- **Single-agent only by design.** The orchestrator serialises per agent; there is no multi-agent scheduler, no agent-to-agent channel, no shared substrate. These arrive with M4+ per the evolution plan in `docs/ways-of-working.md` §Evolution.
