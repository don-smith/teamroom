# M6 — DeepAgents runtime + Archie architect — As Built

*Date: 2026-06-14. Frozen at commit f0d9fec. Future changes happen in a new as-built, not here.*

## 1. What was delivered

M6 shipped **Archie**, Team Room's architect persona, as a persistent agent running the **DeepAgents** runtime. Archie is configured as `runtime: deepagents`, `provider: openrouter`, `model: deepseek/deepseek-v4-flash`, and can receive Team Room mail, inspect the mounted codebase at `/codebase`, and reply in-thread through mail-MCP.

The milestone also made the runtime/provider split concrete across the daemon: runtime selects the container loop (`anthropic`, `langgraph`, `pi`, `deepagents`), while provider selects model-proxy routing (`anthropic`, `lm-studio`, `ollama`, `openai`, `openrouter`). M6 closes with typecheck green, targeted tests green, Archie Docker image building, live Archie/OpenRouter acceptance passing, and the full test suite green except for explicitly environmental LM Studio live tests when LM Studio is not reachable.

## 2. Architecture as built

### Agent configuration and provider routing

Shared types now define model providers and runtimes separately in [`src/types.ts`](../../src/types.ts):

- `Provider = "anthropic" | "lm-studio" | "ollama" | "openai" | "openrouter"`
- `AgentRuntime = "anthropic" | "langgraph" | "pi" | "deepagents"`

Agent config parsing accepts explicit `runtime` and `provider` fields. Archie lives under [`agents/archie/`](../../agents/archie/):

- [`agent.yaml`](../../agents/archie/agent.yaml) declares `runtime: deepagents`, `provider: openrouter`, `model: deepseek/deepseek-v4-flash`, and `lifecycle: persistent`.
- [`AGENTS.md`](../../agents/archie/AGENTS.md) defines the architect persona and Team Room mail expectations.
- [`Dockerfile`](../../agents/archie/Dockerfile) builds the Python/DeepAgents image.
- [`shim.py`](../../agents/archie/shim.py) is the runtime entrypoint.
- `store/.gitkeep` preserves Archie's writable `/store` mount.

[`src/agent-spec/build-spec.ts`](../../src/agent-spec/build-spec.ts) injects both runtime and provider env vars into the container, mints a model-proxy token, mounts `/AGENTS.md` and `/store`, and mounts `/codebase` when configured. [`src/daemon/daemon.ts`](../../src/daemon/daemon.ts) now fails loudly when any `runtime: deepagents` agent is configured without `TEAMROOM_CODEBASE_PATH`, because DeepAgents/Archie acceptance depends on codebase access.

[`src/modules/model-proxy/model-proxy.ts`](../../src/modules/model-proxy/model-proxy.ts) registers an explicit `openrouter` adapter using the shared OpenAI-compatible adapter. OpenRouter requests route through the daemon's local model proxy and add OpenRouter-specific `HTTP-Referer` / `X-Title` headers there, not in the agent container.

### Persistent lifecycle

Persistent lifecycle is implemented in [`src/session-manager/session-manager.ts`](../../src/session-manager/session-manager.ts) and composed in [`src/modules/session-management/session-management.ts`](../../src/modules/session-management/session-management.ts):

- `agent.yaml` may declare `lifecycle: session | persistent`.
- Persistent agents are boot-spawned during daemon startup via `spawnIfAbsent`.
- Persistent agents skip the idle timer.
- Unexpected exit triggers daemon-managed respawn, capped at 10 respawns per daemon lifetime.
- Daemon shutdown kills containers and suppresses respawn.

Archie uses `lifecycle: persistent`, so operators can see the architect container running as part of the team even before the first mail arrives.

### Mail wake reply obligations

M6 added a minimal protocol concept: **reply expectation**. [`src/mail-dispatcher/mail-dispatcher.ts`](../../src/mail-dispatcher/mail-dispatcher.ts) now publishes structured `mail.delivered` events:

```json
{
  "type": "mail.delivered",
  "to": "archie",
  "messageId": "...",
  "threadId": "...",
  "from": "channel:cli:don",
  "replyExpected": true
}
```

Direct CLI/human-to-agent and direct agent-to-agent `to:` mail sets `replyExpected: true`; list fanout and cc-style deliveries set `replyExpected: false`. [`SessionTimerManager`](../../src/session-manager/session-manager.ts) writes these structured events into wake envelopes instead of only sending string tags.

Existing runtime prompts were updated in:

- [`src/agent-runtime/anthropic-worker.ts`](../../src/agent-runtime/anthropic-worker.ts)
- [`src/agent-runtime/langgraph-worker.ts`](../../src/agent-runtime/langgraph-worker.ts)
- [`src/agent-runtime/pi-worker.ts`](../../src/agent-runtime/pi-worker.ts)

All runtimes now distinguish reply-required mail from optional/noisy mail. Final assistant text remains diagnostic; Team Room-visible communication flows through mail tools.

### Archie / DeepAgents runtime

[`agents/archie/shim.py`](../../agents/archie/shim.py) reads JSON wake envelopes from stdin, builds the DeepAgents graph lazily on first wake, discovers mail-MCP tools over HTTP, uses a `FilesystemBackend(root_dir="/codebase")`, and persists LangGraph checkpoints in `/store/langgraph-checkpoint.db`.

The shim chooses the model client by provider:

- `lm-studio`, `openai`, `openrouter`, and `ollama` use `ChatOpenAI` against `TEAMROOM_MODEL_BASE_URL + /v1`.
- `anthropic` uses `ChatAnthropic` against `ANTHROPIC_BASE_URL`.

Archie-specific runtime details:

- Mail MCP tool names are normalized from dotted names (`mail.reply`) to underscore names (`mail_reply`) for model/tool API compatibility.
- OpenAI-compatible DeepAgents profile is compacted for local/hosted non-Anthropic models: smaller prompt surface, no `task`, `write_todos`, or `compact_conversation` tools for M6 acceptance.
- Checkpoint thread id is keyed by Team Room mail thread when structured wake metadata is present. This avoids unrelated live smokes accumulating into one global `archie-main` context.
- Per-wake recursion limit is capped at 16 to avoid runaway exploration.
- Archie has an **Archie-only** fallback: if a reply-required wake ends with final assistant text but no successful `mail_reply`, the shim sends the text through MCP `mail.reply` directly. This is treated as a safety-net/failure path, not normal success.

### Runtime telemetry bridge

Containers can emit structured stdout log events (`{ "type": "log", "level": "warn", "msg": "..." }`). M6 wires persistent container log events through session management into the event bus. The daemon subscribes and logs at warn level for Archie's safety-net events:

- `agent.tool_call.invalid` — malformed/invalid model tool calls, including failed `mail_reply` JSON.
- `agent.reply_required.fallback_used` — Archie fallback sent mail because a reply-required wake did not produce a successful tool result.

This keeps the fallback from hiding the underlying failure mode.

### Skills and landing process

During closeout, the repo-managed `.agents/skills/` tree was removed. Skills are now consumed from installed npm workflow-skill packages (e.g., `@juicesharp/rpiv-pi`, `@locksmithdon/dons-flow`) and invoked via `/skill:name` or `<skill>` blocks. [`AGENTS.md`](../../AGENTS.md), [`docs/ways-of-working.md`](../ways-of-working.md), and related references were updated to describe this model. The `land` skill now describes Team Room's branch/milestone landing process and delegates to `as-built-documentation`, `writing-retros`, and `capturing-learnings`.

## 3. Key design decisions and their WHY

- **Rescope M6 to Archie/DeepAgents only.**
  - **Why:** `main` already shipped `pi-coder` as the coding teammate. Adding another coding agent or Hermes runtime would dilute M6. The valuable proof is an architect persona on a mature external runtime.

- **Remove Hermes/Dev from active M6 scope instead of deferring it to M6.1.**
  - **Why:** The user explicitly wanted Hermes/Dev removed, not carried as a near-term follow-up. The branch should close around one clear outcome: Archie.

- **Keep runtime and provider separate.**
  - **Why:** A runtime is the agent loop/container contract; a provider is model routing. Coupling them would prevent combinations like DeepAgents + OpenRouter or Pi + OpenAI-compatible providers.

- **Make OpenRouter a first-class provider.**
  - **Why:** Ambient `OPENROUTER_*` selection inside Archie was brittle and could hijack provider choice. Explicit `provider: openrouter` in `agent.yaml` makes routing inspectable and testable.

- **Require `/codebase` for `runtime: deepagents`.**
  - **Why:** Archie is an architect persona and DeepAgents filesystem behavior is central to acceptance. Missing `/codebase` should fail loudly at daemon boot, not produce opaque runtime tool errors.

- **Represent reply obligations in the mail wake protocol.**
  - **Why:** Agents should not spam every wake, but direct human/agent requests should not vanish into final assistant text. `replyExpected` gives runtimes a protocol-level distinction between required reply and optional silence.

- **Use an Archie-only fallback, but make it loud.**
  - **Why:** DeepAgents/DeepSeek once attempted `mail_reply` with malformed JSON. The fallback protects the user-visible reply path, but telemetry must surface the failed tool call so the system problem is not hidden.

- **Lazy-build Archie's DeepAgents graph on first wake.**
  - **Why:** Docker "Up" should not depend on MCP/model reachability. First-wake latency is acceptable for M6; readiness remains a known limitation.

- **Move skills to package-level workflow skill imports.**
  - **Why:** Team Room is multi-model. A repo-local skill tree would create duplication and conflict across models. Consuming skills from installed npm packages (invoked via `/skill:name` or `<skill>` blocks) keeps the codebase focused and skills shared across environments.

## 4. Adaptations during execution

- **After merging `main`, M6 changed shape.** The original branch carried a multi-harness direction. After `main` landed Bun and `pi-coder`, M6 was rewritten around DeepAgents + Archie.

- **Anthropic fallback needed Anthropic-shaped calls.** Early Archie fallback used `ChatOpenAI` against Anthropic proxy routes and hit the wrong request shape. The branch switched Anthropic provider handling to `ChatAnthropic` for `/v1/messages`.

- **LM Studio was viable for transport but not for Archie acceptance.** Gemma and Qwen local models reached model calls but did not reliably complete the mail/tool workflow. This motivated explicit OpenRouter support for a hosted non-Anthropic acceptance path.

- **OpenRouter auth failure was an inherited shell-env issue.** The root `.env` key was valid, but an inherited stale `OPENROUTER_API_KEY` overrode it because `loadEnvFile()` intentionally does not overwrite shell vars. Live smokes now unset stale env vars when validating root `.env` behavior.

- **DeepAgents checkpoint persistence mattered immediately.** Fixed `archie-main` checkpointing caused unrelated smoke tests to accumulate huge context. Archie now keys checkpoint thread ids by Team Room mail thread when structured metadata is present.

- **Prompt-only reply discipline was insufficient.** Structured wake metadata improved behavior, but one run produced malformed `mail_reply` JSON. M6 added bounded prompts, recursion cap, warning telemetry, and Archie-only fallback.

- **Landing practices changed during closeout.** New imported skills and the `land` skill were added, initially as repo-level `.agents/skills/`, later consolidated into npm workflow-skill packages. `docs/ways-of-working.md` now documents skill inventory and the Team Room landing path.

## 5. Known limitations and debts for future work

- **First-wake build retry cap resolved.** `agents/archie/shim.py` now caps first-wake build attempts at `MAX_BUILD_RETRIES = 3`. After three consecutive build failures, the process exits with code 1 so daemon-managed respawn can engage.

- **Docker "Up" is not first-wake readiness.** Archie builds the DeepAgents graph lazily, so the first wake pays MCP discovery/model setup latency. Future work may add a lightweight readiness probe or explicit readiness telemetry.

- **Persistent respawn counter now resets on clean exit.** `SessionTimerManager` resets the counter when a persistent container exits with code 0, so occasional crashes do not accumulate toward the lifetime cap.

- **Fallback provider/model ordering is not implemented.** OpenRouter is explicit, but per-agent ordered fallback providers remain future work.

- **Archie has no durable persona memory yet.** `/store` checkpoints persist runtime state, but M7 remains the per-agent memory milestone.

- **Archie is operational, not fully mature.** M6 proves that Archie can join the team and answer an architectural question. Skills, evals, long-term responsibilities, and deeper onboarding are future work.

- **Full `bun test` still includes environmental LM Studio live tests.** The branch validation records those failures as environmental when LM Studio is not running; targeted non-environmental tests pass.
