# Team Room M2 — As Built

*Date: 2026-04-19. Frozen at commit. Future changes happen in a new as-built, not here.*

## 1. What was delivered

Milestone 2 — **"Model abstraction layer."** Two agents run end-to-end against two different backends through a single in-daemon credential proxy. `studio-assistant` (the M1 `assistant`, renamed) talks to local LM Studio via the OpenAI-compatible SDK. The new `claude-assistant` talks to real Anthropic via the user's Claude Code subscription (OAuth). Real upstream credentials never reach the container: the host-side `LocalModelProxy` mints a per-turn ephemeral routing token, the container sends it on every outbound call (as `x-api-key` or `Authorization: Bearer`), and the proxy substitutes the real credential before forwarding upstream. The smoke test passes end-to-end for both agents, including a multi-turn codeword-recall check that proves conversation history is intact across the per-turn container teardown.

Exit criteria from the spec, all met:

- Two agents concurrently against two backends (studio-assistant → LM Studio; claude-assistant → Anthropic via OAuth, API-key as documented fallback).
- Real credentials never in container env / stdin / `docker inspect` — only the routing token is exposed.
- Smoke test passes against real LM Studio + real Anthropic; multi-turn codeword recall confirmed for both.
- Full unit + integration suite green (30 co-located unit test files across `src/`, 4 integration tests under `tests/integration/`).
- Span-shaped log records (`turn.started`, `model.call.completed`, `turn.completed`, …) carry a shared `traceId`; turns reconstruct from JSONL alone.
- Five M1 debts absorbed (see §4, items e–i).

**One major adaptation from the spec as written.** Spec §6.2 described a server-to-server OAuth exchange (`POST /api/oauth/claude_cli/create_api_key`) to trade a long-lived OAuth token for a short-lived temp API key. Anthropic gates that endpoint for tokens issued via `claude setup-token`. Direct use of the OAuth token against `/v1/messages` was *also* gated (429 with no `anthropic-ratelimit-*` headers — i.e. scoping, not real rate-limiting). Final landing: the container uses `@anthropic-ai/claude-agent-sdk`, which spawns the Claude Code CLI as a subprocess; the subprocess honours `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN` and constructs requests with the full Claude Code identity Anthropic's gating expects. Our proxy substitutes the real credential just like any other request. Pattern lifted from NanoClaw. See §4.

## 2. Architecture as built

### Processes and boundaries

- **`teamroom` CLI (host, short-lived).** Unchanged from M1 — `serve`, `send`, `tail`, `status`.
- **Daemon (host, long-lived).** Still the sole long-running process. Now owns one extra in-process listener: `LocalModelProxy`, bound to `127.0.0.1` on an OS-assigned port. Discovers agents at startup by scanning `agents/` and registers each in SQLite.
- **Model proxy (host, in-daemon).** In-process `http.createServer` on `127.0.0.1:<ephemeral>`. The daemon injects its URL into every spawned container as both `TEAMROOM_MODEL_BASE_URL` and `ANTHROPIC_BASE_URL` (two env-var names, one destination). The container reaches the proxy at `http://host.docker.internal:<port>`. The proxy uses Node's `https` to talk to real Anthropic; plain `http` for LM Studio.
- **Agent container (Docker, per-turn, ephemeral).** One per inbound message, `--rm` on exit. Named `teamroom-<agent>-<turn-id-prefix>` so `docker ps`/`logs` is meaningful. Mounts `/AGENTS.md` (now **read-write**, was RO in M1) and `/store` (read-write). Stdin: JSON envelope. Stdout: JSONL events, at least one `{type:"reply", body}`.

The host/container split is unchanged. The proxy is a new piece on the host side; nothing about the container contract except env-var population changed.

### `ModelProxy` and adapters

`ModelProxy` is a four-method interface (`start / stop / mint / evict`) implemented once by `LocalModelProxy`. On every request the proxy:

1. Extracts the routing token from either `x-api-key` (Anthropic SDK shape) OR `Authorization: Bearer <token>` (OpenAI SDK shape, and the shape the Claude Code CLI uses). **Accepting both was a pivot from the spec** — the CLI-as-HTTP-client lands tokens in `Authorization`, not `x-api-key`.
2. Looks the token up in `TokenRegistry` → `TokenEntry { agentId, turnId, traceId, provider, model }`. Unknown token → 401 + `model.call.rejected` span (logs only the first 8 chars of the token).
3. Picks the `ProviderAdapter` for `entry.provider`. `adapter.resolveAuth(headers)` swaps the routing-token placeholder for the real upstream credential (API key for LM Studio / Anthropic API-key mode; cached OAuth token for Anthropic OAuth mode).
4. Forwards to `adapter.upstreamUrl()` preserving path/method/body. Copies response back after stripping hop-by-hop headers.
5. Emits a `model.call.completed` span with `traceId`, `spanId`, `provider`, `model`, `httpStatus`, `latencyMs`, `inputTokens`/`outputTokens` (from `adapter.extractUsage`), and on 2xx-with-no-usage a 200-char `bodyPreview` for operator debuggability.
6. **OAuth credential-refresh retry.** If the upstream returns 401 and the adapter is OAuth-mode and `onUpstreamUnauthorized` is defined, the proxy evicts the cached temp key and retries the original request exactly once. This is the only retry the proxy performs.

Routing-token and real-credential separation: the registry stores only the `TokenEntry` (agent/turn/trace/provider/model). Real upstream credentials live in the adapter; they are resolved per-call and never appear in the registry.

### `AnthropicAdapter` — OAuth mode details

The shipped OAuth path is simpler than the spec's planned exchange-and-cache:

- `AnthropicOAuthCache` exists and passes tests for the exchange-with-cache pattern (single-flight fetcher, safety margin, eviction on 401).
- `daemon.ts` wires it with a `directOAuthPassthrough` "exchange" that returns the OAuth token itself as the temp key with a 1-year `expiresAt`. The cache machinery still runs — it just holds one entry.
- `resolveAuth()` sends the (effective) temp key as `Authorization: Bearer <token>` (not `x-api-key`, which is only for raw API keys) and merges `anthropic-beta: oauth-2025-04-20` into any existing beta flags. These two details are load-bearing — without both, Anthropic rejects the request.

The exchange-with-cache scaffolding is kept intentionally: it's the right shape if Anthropic ever opens up a working programmatic exchange, and the unit tests still cover that path against fake upstreams.

### Agent population

- `agents/studio-assistant/` (renamed from `agents/assistant/`) — `agent.yaml` now declares `provider: lm-studio` explicitly.
- `agents/claude-assistant/` — new. `agent.yaml` declares `provider: anthropic`, `model: claude-opus-4-7`. Dockerfile uses `node:22-alpine`, installs `@anthropic-ai/claude-agent-sdk` (via `npm ci`) and globally installs `@anthropic-ai/claude-code` so the SDK has a binary to spawn.
- `store/` for claude-assistant accumulates three things across turns: `conversation.jsonl` (Team Room's portable log, written by `runtime.ts`), `anthropic-session.txt` (SDK session-UUID sidecar used for `resume:`), and `claude-sdk/` (the CLI's own state directory — session JSONL, config, backups). `store/work/` is a stable cwd the SDK groups sessions under. Two-sources-of-truth for conversation history is documented in `agents/README.md` as intentional.

### Credential discovery (daemon startup)

Order resolved in `src/env/anthropic-credentials.ts`, order preserves OAuth-preferred:

1. `CLAUDE_CODE_OAUTH_TOKEN` from `.env` → OAuth mode.
2. **macOS only**: system Keychain entry `Claude Code-credentials` (via `security find-generic-password`) → OAuth mode. Raw `sk-ant-oat01-...` or JSON blob accepted.
3. `~/.claude/.credentials.json` (Linux/Windows) → OAuth mode. Parses common shapes (`oauth_token` / `access_token` / `token`, optionally nested under `claudeAiOauth` / `oauth` / `credentials`).
4. `ANTHROPIC_API_KEY` from `.env` → API-key mode.
5. None of the above → daemon still starts but any `provider: anthropic` agent's turns fail fast with `missing_credential`.

Surfaced at boot via the `model proxy started` log line with `anthropicAdapterPresent: true|false`.

### Turn lifecycle (delta from M1)

The M1 lifecycle stands. Inside `processTurn`:

1. Create the `turns` row (`pending`).
2. Attach it to the inbound message (`messages.turn_id`).
3. **`markRunning(turnId, "pending-spawn")` BEFORE `runner.run()`** (M1 debt #1 part 1). The real container id replaces `"pending-spawn"` once known.
4. Refuse `provider: anthropic` turns with `missing_credential` if no Anthropic adapter is wired — emits a `turn.errored` bus event, returns without minting.
5. `modelProxy.mint({agentId, turnId, traceId, provider, model})` → routing token.
6. Publish `turn.started`; spawn container with `{TEAMROOM_*}` and `{ANTHROPIC_BASE_URL, ANTHROPIC_AUTH_TOKEN}` env (populated unconditionally so a future agent that switches providers Just Works).
7. Stream stdout events; `reply` becomes an outbound `messages` row + `message.outbound` bus event.
8. Container exit → `turn.completed` or `turn.errored` (stderr tail surfaced in log for debuggability).
9. `finally { modelProxy.evict(token) }` — unconditional, so the registry never leaks.

`reconcile.ts` now sweeps aged-`pending` turns (older than 60 s without a container id) in addition to orphaned `running` rows, closing the M1 blind spot where a daemon crash between task 3 and runner-return would leave a turn forever.

### Span vocabulary

Log events carry `traceId`, `spanId`, sometimes `parentSpanId`, `agentId`, `turnId`, plus event-specific fields. M2 events:

- Daemon: `turn.started`, `turn.completed`, `turn.errored`.
- Proxy: `model.call.completed` (ok, `upstream_error`, `upstream_timeout`, `client_disconnected` in shape but not-yet-emitted), `model.call.rejected` (missing/unknown/no-adapter/auth-error).

The proxy does **not** publish bus events in M2 (spec §8 deferral — bus evolution is an M3 question). The daemon's `turn.started`/`turn.completed`/`turn.errored` bus events from M1 still fire, with the same logical meaning as their log counterparts; that intentional duplication is documented in `src/bus/README.md` and the spec.

### Data model

SQLite schema unchanged from M1. Only behaviour changes: `turnRepo.findAgedPending(cutoff)` is new (used by reconcile), and `markRunning` is called earlier in the lifecycle. No new tables; no new columns.

### Testability

M1 principles held — every effectful dependency behind an interface, tests use real in-memory implementations (`:memory:` SQLite, `InMemoryBus`, `FakeRunner`, real `http.createServer` on ephemeral ports for the proxy + fake-upstreams), zero `vi.mock`/`jest.mock`. Co-located unit tests; cross-module in `tests/integration/`. `tests/integration/` gained:

- `proxy-end-to-end.test.ts` — full daemon + proxy + fake-upstream composition. Three scenarios: API-key, OAuth, provider isolation.
- `lm-studio-real.test.ts`, `anthropic-oauth-real.test.ts` — real-upstream integration tests. Not opt-in: if creds are discoverable they run, otherwise they fail loudly (per `feedback_teamroom_no_skipped_tests`).

## 3. Key design decisions and their WHY

- **Proxy runs in-daemon as an in-process HTTP listener.**
  - **Why:** minimises long-running process dependencies (per the locked-in M1 principle). A separate proxy process would mean another thing that can be partially configured, partially alive, or skewed from the daemon's view of agents. In-process, the proxy shares the daemon's registry by reference and its lifecycle is trivial.

- **Container is mode-agnostic; all OAuth mechanics live in the proxy.**
  - **Why:** the container should not know or care whether the operator is on a subscription or an API key. Substitution happens one layer back. This is a meaningful simplification over patterns (like the naive NanoClaw interpretation) where the container does the exchange — per-turn exchange round-trips drop to at most one per temp-key TTL, the container-side code is identical for both modes, and future "multiple agents on one subscription" works naturally because the cache is keyed by the OAuth token, not the agent.

- **One `ProviderAdapter` per backend; `LocalModelProxy` does not know about providers directly.**
  - **Why:** adding a third provider is a one-file change (new adapter + register it in `daemon.ts`). The proxy handles only the transport concerns (routing, header pass-through, timeouts, retries); the adapter owns its upstream URL, auth-header shape, and response-body usage extraction.

- **Routing token is random per turn; registry is in-memory; eviction is in a `finally`.**
  - **Why:** in-memory matches M1's "no long-running dependencies" principle. A daemon crash wipes the registry — reconcile sweeps resolve the DB rows; the container fails with a 401 from the proxy if it somehow keeps running. `finally`-eviction means no registry leak on any path, including container crashes and exceptions.

- **Accept routing token in both `x-api-key` AND `Authorization: Bearer`.**
  - **Why:** the Anthropic SDK sends `apiKey` as `x-api-key`; the OpenAI SDK sends it as `Authorization: Bearer`; the Claude Code CLI (via `claude-agent-sdk`) uses `Authorization: Bearer`. Accepting both means no per-SDK plumbing in the proxy.

- **Claude-assistant uses `@anthropic-ai/claude-agent-sdk` (→ Claude Code CLI subprocess), not `@anthropic-ai/sdk` directly.**
  - **Why:** Anthropic gates programmatic OAuth tokens against `/v1/messages`. The gate accepts requests that Claude Code itself sends — full User-Agent, anthropic-beta flags, etc. — but rejects bare-SDK calls. Rather than reverse-engineer and maintain those headers, we run the real CLI in the container and let it make the requests. NanoClaw uses the same pattern, and we only arrived there after burning iteration cycles on the bare-SDK path (retro §2).

- **`directOAuthPassthrough` instead of a real OAuth exchange.**
  - **Why:** the exchange endpoint (`POST /api/oauth/claude_cli/create_api_key`) is gated for `claude setup-token` outputs. Those tokens are themselves long-lived (`sk-ant-oat01-...`, ~1 year) and Anthropic accepts them directly with `Authorization: Bearer + anthropic-beta: oauth-2025-04-20`. We keep the cache scaffolding because it's the right shape if the exchange endpoint ever opens up, but the shipped "exchange" is a passthrough.

- **`markRunning` before `runner.run()`, with a `"pending-spawn"` placeholder.**
  - **Why:** closes the M1 reconciler blind spot — a daemon crash between turn-create and runner-return left a `pending` row with no `container_id` that nothing would ever reclaim. Now every row transitions `pending → running` before the container starts, so the reconciler's "orphaned running" sweep catches it. The 60s aged-pending sweep covers the tiny window before `markRunning` itself runs.

- **`anthropic-beta: oauth-2025-04-20` *merged* (not set) into request headers.**
  - **Why:** the SDK or CLI may already be sending other beta flags (`messages-2023-12-15`, `tools-2024-05-16`, etc.). Replacing the header strips those; merging preserves both. Learned the hard way — real Anthropic rejects requests with half the expected flags.

- **Two env-var names for one URL: `TEAMROOM_MODEL_BASE_URL` AND `ANTHROPIC_BASE_URL`.**
  - **Why:** `ANTHROPIC_BASE_URL` is fixed by Anthropic (the Claude Code CLI reads it directly). `TEAMROOM_MODEL_BASE_URL` is our own name for the OpenAI-compat path. Populating both unconditionally means a future provider switch doesn't require a container respawn just to update env.

- **Container name encodes agent + turn-id prefix (`teamroom-<agent>-<turnId-8>`).**
  - **Why:** `docker ps` during a live turn is immediately meaningful without cross-referencing. The 8-char suffix keeps names unique across concurrent turns of the same agent. Cheap, diagnostic-multiplying.

- **AGENTS.md is mounted read-write (was read-only in M1).**
  - **Why:** self-improvement loops (M7+) need this. No cost to land it now — M2 touches the mount anyway — and no current agent writes back, so nothing breaks.

- **`agents/README.md` at the repo level, not just per-agent READMEs.**
  - **Why:** the studio-assistant and claude-assistant folders have *intentionally* different shapes (the SDK-stateful claude-assistant `store/` has files the lean studio-assistant `store/` doesn't). That asymmetry is the kind of thing that confuses a future maintainer into "normalising" one of the two; the README is where we call the asymmetry out and explain why.

- **`tsconfig.json` excludes `**/*.test.ts` from `npm run typecheck`.**
  - **Why:** kept from M1, but flagged as a schema-change risk-multiplier during M2 (Task 6: required-field additions to `AgentConfig` silently left fixtures type-broken). Pre-commit `tsc --noEmit --strict` against test files is a manual workaround; a proper `tsconfig.test.json` is an M3 follow-up.

## 4. Adaptations during execution

- **OAuth path: planned server-to-server exchange → claude-agent-sdk subprocess.** Spec §6.2 described trading a long-lived OAuth token for a short-lived temp key via `POST /api/oauth/claude_cli/create_api_key`. Anthropic gates that endpoint (403 for tokens from `claude setup-token`). Direct OAuth-to-`/v1/messages` with Bearer was also gated (429 with no rate-limit headers). Final landing: `@anthropic-ai/claude-agent-sdk` in the container, which spawns the Claude Code CLI subprocess; `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN` route it through our proxy. Commit `973e5c4` is the pivot. The exchange-and-cache machinery in the proxy is kept but wired to `directOAuthPassthrough`.

- **Proxy accepts routing token via `Authorization: Bearer` in addition to `x-api-key`.** Commit `23dfb32`. The Claude Code CLI sends `Authorization: Bearer`, not `x-api-key`; adding the second lookup path was cheaper than forcing a header translation layer.

- **OpenAI SDK baseURL needs `/v1` appended.** Commit `146db89`. The OpenAI SDK adds `/chat/completions` but not `/v1`; LM Studio expects `/v1/chat/completions`. Adjusted in `agent-runtime/main.ts`, not in the proxy.

- **macOS Keychain support for OAuth discovery.** Commit `8cf418e`. On macOS, Claude Code stores its OAuth token in the system Keychain (service `Claude Code-credentials`), not in `~/.claude/.credentials.json`. Discovery now probes the Keychain between env-var check and file-fallback check. Smoke test precondition updated to match.

- **Explicit session-id sidecar for claude-agent-sdk resume.** `store/anthropic-session.txt` is written after each turn and read at the start of the next. `store/claude-sdk/` is the SDK's own `CLAUDE_CONFIG_DIR`, pointed at `/store` so session files survive the `--rm` teardown. `store/work/` is a stable cwd so the SDK's per-cwd session grouping works. Commit `e92954d`.

- **Integration-test gate dropped to fail-loud.** Commit `08e7372`. Initial integration tests used an opt-in gate (`if (!CREDS) return;`), which Claude interpreted as "passing." User pushback: a skip is not a pass. Now the real-upstream tests fail if creds aren't discoverable. Captured as `feedback_teamroom_no_skipped_tests`.

- **LM Studio base URL default: `localhost`, not `host.docker.internal`.** Commit `95b4ceb`. The proxy runs on the host; `host.docker.internal` only resolves *inside* containers. That hostname is what the container uses to reach the proxy, not the other way around. `TEAMROOM_MODEL_BASE_URL` default was wrong in the first pass of `daemon/main.ts`.

- **`.gitignore` for agent store dirs: contents-only.** Commit `f0badbb`. Git cannot re-include `store/.gitkeep` via `!` negation if `store/` itself is excluded as a directory. Existing `studio-assistant` rule had the same bug from M1; silently dropped `claude-assistant/store/.gitkeep` during task landing. Fix: `agents/*/store/*` (contents), not `agents/*/store/` (the dir itself). Same-bug-twice, now fixed in both places.

- **Span event schema aligned with spec §5 vocabulary.** Commit `34d8af9`. First-pass proxy emitted its own ad-hoc event names; harmonised to the spec vocabulary (`model.call.completed`, `model.call.rejected`). Tests followed.

- **Turn-errored log surfaces container stderr.** Commit `613fe60`. When a container exit-1'd, the DB had the stderr tail but the log just said "turn errored." Turn-processor now includes a `stderrTail` field (capped at 2KB) on the warn log so failures are debuggable from the log alone.

- **Proxy logs `bodyPreview` on 2xx-no-usage responses.** Commit `ed616f2`. LM Studio sometimes returns HTTP 200 with an `{error}` body when a model id is wrong; the proxy would emit `model.call.completed status=ok` with no usage, and the operator had no visible symptom. A 200-char preview on the span (only when both usage fields are missing) makes this a one-line diagnosis.

- **Aggressive plan-template drift caught in flight (≥11 sightings).** Logger API mismatches, CapturingLogger constructor shape, AnthropicAdapter response-envelope SDK validation, invalid TypeScript syntax in plan snippets, missing files from task file lists, OAuth-exchange endpoint/header/field-name divergences from spec. None escaped to production. Retro §2 is the fuller accounting; tactically, the implementer + reviewer subagents caught the rest during task landing.

- **Five M1 debts absorbed in M2 (see retro §appendix for the full list):**
  - **(e) Reconciler `pending` blind spot** — `markRunning` moved before `runner.run()`; aged-`pending` sweep added (`f79473a`, `c2df867`).
  - **(f) Daemon shutdown polish** — static `fs` import; PID file unlinked on clean stop; idempotent `stop()` with `let stopped = false` guard (`045a562`).
  - **(g) `parseEvent` spread ordering** — typed `type` field now always wins over malformed JSON payload (`652a43e`).
  - **(h) Agent-onboarding runbook skeleton** — `docs/runbooks/agent-onboarding.md` written alongside hiring claude-assistant (`8660bbf`).
  - **(i) `@types/node` + `engines.node` to 22** — `npm ls` confirmed no transitive `<22` dep; bumped both (`7c8dc62`). Studio-assistant's `Dockerfile` is still on `node:20-alpine` — see §5.

## 5. Known limitations and debts for future work

Flagged so M3 planning can pick them up deliberately. Full context: retro §5 action items and `docs/m3-followups.md`.

- **Phase-3 cleanup batch (land before M3 starts).** Retro §5 item 5; tabled during Phase 3 as "defensible deferrals" but now a known chunk of polish work:
  - Proxy `client_disconnected` status + double-respond protection (`req.on("close", ...)`).
  - Proxy request-body size cap (default ~10 MB).
  - Proxy wall-clock deadline alongside idle timeout (or document the idle-timeout-resets-on-activity behaviour in `Opts`).
  - Proxy auth-resolution failure: 500 → 502 (more accurate when the OAuth exchange itself fails).
  - `emit()` event/msg duplication — either require `event` (no `?? ""` fallback) or drop the duplication and have tests read `r.event`.
  - `AgentConfig` validators (Tasks 6/10/11/14): consistent split of missing-vs-invalid with offending-value echo `(got '${String(provider)}')`.
  - New `tsconfig.test.json` extending the main one with tests included; wire into `npm run typecheck` so schema changes catch fixture drift at typecheck time.
  - `studio-assistant/Dockerfile` bump `node:20-alpine` → `node:22-alpine` to match `engines.node`.
  - Extract `discoverAnthropic` duplication out of `cli/serve.ts` and `daemon/main.ts` into a shared `src/env/credentials.ts` module.

- **M3 follow-ups** — tracked in `docs/m3-followups.md`:
  1. Multi-model-per-agent and per-request model selection (`TokenEntry` already carries a comment anticipating the list-shape).
  2. Streaming model responses — triggers three coupled refactors (SSE pipe, `LocalModelProxy` buffering, container↔proxy transport).
  3. Tool-call telemetry as child spans (vocabulary is already compatible).
  4. CLI as a `Channel` impl when channels become first-class.
  5. `teamroom debug-agent` CLI (deferred Task #38 from M2).

- **Proxy has no per-agent retry policy, no rate-limit awareness, no per-agent budgeting.** M2 keeps the proxy deliberately dumb; any retry/budget lives with the agent runtime when there's a real reason. The single exception is the one-shot OAuth credential-refresh retry on 401.

- **Bus rewrite not started.** The span-shaped records are log-only in M2 per spec §8; migrating to bus events is an M3 question. `src/bus/README.md` has the YAGNI line ("don't add events without a real consumer") as a hedge against drift.

- **No CI.** Still post-M1 deferrable. Full suite runs locally in a few seconds.

- **Claude-assistant has `allowedTools: []`.** Non-tool-using chat only. Tool loops land in M3 alongside the tool-call telemetry slot.

- **Single-agent serialisation per agent.** Inherited from M1; orchestrator still single-loop. Multi-agent scheduling is M4+ territory.

- **Windows support not exercised.** Credential discovery has a Linux/Windows file branch; actual Windows runs haven't been tested. Any Windows-specific quirks (path separators, Keychain absence) will surface when someone tries it.
